      Before you start

      This console records demonstrations from the leader arm. It only listens to the arm feed and the cameras; it never moves the arm.

      1. 1Choose what to record. Pick the task; every take in a session is labelled with it.
      2. 2Check cameras and arm. The console looks at the wrist camera, the overhead camera and the arm feed, and tells you what to fix.

      • Secure the arm, clear the bench and keep the emergency stop within reach.
      • Start the arm feed the way you always do, with writes disabled. The console never starts it.

        How a session works

        1. Start a session. Choose the task, check the cameras and arm feed, press Start session.
        2. Record takes. Set the scene, press Start recording, do the move, press Stop, then say whether it worked.
        3. Pause. Releases the cameras and arm feed; every saved take stays.
        4. Continue. From Home or Sessions, picks the session up where it was.
        5. Finish. Marks the session finished and shows its summary. Reopen it later to add takes.

        Before you connect

        1. Make the rig safe. Secure the arm, clear the workspace and keep the e-stop within reach. Follow the approved power and controlled-stop procedure. Never remove torque from an unsupported arm.
        2. Keep working teleoperation unchanged. The leader drives the follower through the sync cable. The PC reads follower state. Only one process may own the follower USB connection.
        3. Use a verified read-only arm feed. Writes must be disabled and startup torque unchanged. The console does not start or reconfigure that source.
        4. Assign the two camera roles. Wrist camera on the wrist; overhead camera fixed above the scene. Close preview apps. A listed USB device is not proof of a working stream.

        The console never moves the arm, starts a driver, changes torque, launches a bridge or arms a policy.

        Procedures

        Task timing controls are not in this console

        Takes count toward the dataset only when the task has a timed window registered in the repository. You can do practice runs before that.

        Take timing registration, read only
        1. Choose a skill and time the real task using the approved physical procedure.
        2. Record the observed timing, chosen minimum and maximum, rationale, operator and date in docs/ludo_flagship/DECISIONS.md.
        3. Register the reviewed window in config/synria_tasks.json. The console does not edit this registry.
        4. Reopen the console and confirm the task shows “registered”; unset windows continue to block qualifying sessions.
        There are no timing inputs here by design. Do not use suggested presets, synthetic runs or the practice run length as a real take window.

        Physical training curriculum · staged, not all recordable yet

        Keep datasets single-task. The registry above is the authority for what can be recorded; these next skills are a planning guide, not extra task choices.

        Object-control foundations

        • Pick a cup: approach the marked cup, grasp without tipping, lift clear, hold briefly, and present it for inspection. Pass only when the cup is securely held and upright.
        • Place a cup: transfer the grasped cup to a marked target, release, and retract. Pass only when it is upright within the target boundary and the gripper is clear.
        • Pick a die: grasp one die from the marked start zone without moving nearby objects; lift and hold for visual confirmation.
        • Place a die: transfer the held die to a marked square or tray, release, and retract. Pass only when the die is at rest inside the target boundary.

        Fixed-scene roll skills

        • die_into_cup: release the die inside the cup at its fixed mark.
        • roll_and_dump: contain and agitate the die in the cup, then dump it into the fixed landing tray; pass only when the die is at rest in the tray and the cup remains upright.
        • cup_return: return the cup upright to its marked home and retract.
        • Bounded table toss: a later, low-energy release into a contained landing tray—not an unrestricted throw. Require a reviewed safe release envelope and tray containment before enabling it.

        Board-play extensions · deferred

        After the roll skills are validated, plan token pickup, one-square placement, complete token moves, and capture/return-to-start as separate tasks. These need their own goal protocol and must not enter the current roll datasets.

        For each future task, preregister one observable success rule, task-specific minimum and maximum duration, fixed scene, allowed variation, camera evidence, failure labels, and recovery/discard criteria. Vary one scene factor at a time. Keep attempts with quality-valid task failures; exclude only capture or scene faults under the D1 protocol.

        Implemented, unmeasured. No hardware validation. Read-only toward the arm: the console only listens to the arm feed and the cameras.

        Shut down

        Shutting down stops the console server for everyone using it. Takes already saved stay on disk. Pause or finish the session first.
